## What changed

No species or family documents changed. The work is entirely on `/identify/photo`, the model-publish path, credits, tests, and the handoff docs. The only file under `docs/` that changed is `docs/identify-photo-model.md`.

### Features

- **Automatic find-and-crop (issue 180, PR #186, commit `b6439e8b`).** When a photo is opened on `/identify/photo`, a second, smaller model finds the bird, the page crops to the largest bird box and goes straight to recognition. The crop is shown beside each result; “Change the crop” opens the crop view on that square. If no bird is found, the crop view opens as before, with a line saying so. “Another bird in this photo” cycles through other boxes that score at least 0.5 (PR #186 body; `STATE.md` “Finding the bird automatically”; `docs/identify-photo-model.md` “Finding the bird and cropping to it”).
- **Live camera naming (issue 181, PR #187, commit `9af185da`).** `/identify/photo` gains a “Live: name birds as you point” button under the two photo inputs, offered only when the detector is loaded and the browser has `getUserMedia`. The camera is shown in the page, the bird is outlined, and a name (with a link) appears under the video. “Hold” freezes the frame, releases the camera, and runs the ordinary photo path. Start/Stop; it also stops when the page is hidden, when the camera track ends, after 60 seconds with no bird in view, and when three frames in a row each take over a second (PR #187 body; `STATE.md` “Live mode on the photo page”).
- The page intro, tips, reading notes, Markdown and JSON views, and the agent-facing description in `src/static.js` were updated to describe find-and-crop and Live (patches to `src/identify-photo-page.js`, `src/static.js`).

### Data

- `data/index/credits.json` gained an EfficientDet-Lite0 credit (Apache-2.0, COCO 2017, LiteRT.js runtime), generated by `scripts/seed.mjs` from the new `PHOTO_DETECTOR_CREDIT` in `src/identify.js` (patches to those three files; PR #186). No species, family, or population files changed.

### Architecture

- **A second on-device model**, Google's EfficientDet-Lite0 (COCO, Apache 2.0), 4,562,456 bytes (4.4 MiB), version folder `models/efficientdet-lite0-coco-raw-1/`, constants in `PHOTO_DETECTOR` in `src/identify.js` (`version`, `file: bird-detector.tflite`, `inputSize: 320`, `sha256`, `birdClass: 15`, `score: 0.3`, `overlap: 0.5`, `margin: 0.35`, `another: 0.5`). It is not trained in this repo (`docs/identify-photo-model.md`; `training/identify-photo/README.md` steps 10–12).
- **The shipped file is not Google's file byte for byte.** LiteRT.js cannot run the last step (`TFLite_Detection_PostProcess`: variable-size outputs fail with “Insufficient buffer size”). `training/identify-photo/strip-detector.py` removes that step only; the page picks boxes itself (`anchorBox`, `birdBoxes` in `src/client/identify-photo.js`). Weights are unchanged (PR #186; `STATE.md`; `docs/identify-photo-model.md`).
- **The detector is optional everywhere.** The recogniser still loads without it. A visitor who already has the recogniser is not sent the detector unasked; the page offers it (`#identify-upgrade`). In the installed app it is part of the “Photo recognition model” option and shows as an update (`STATE.md`; `src/offline-app.js` adds the detector file to that option's list, with its SHA-256).
- **Publish path.** `pnpm run models:publish -- --only photo` now also uploads the detector and needs `data/models/bird-detector.tflite` (or `--photo-detector`). The detector is **not** republished on Hugging Face (`scripts/publish-models.mjs`; `README.md` one-line change; `docs/identify-photo-model.md`). `STATE.md` at `main` still says: **“Not published yet: run `pnpm run models:publish -- --only photo` before deploying.”** Until then the page loads the recogniser, finds no detector, and works as it did before, with an offer to download the detector that fails (PR #186 “Before deploying”).
- **Quoted download** goes from 20.2 MiB to 24.6 MiB (9.3 MiB recogniser + 4.4 MiB detector + 10.9 MiB runtime) (`photoDownloadBytes` / `photoDownloadSummary` in `src/identify.js`; PR #186).
- **Permissions.** Only the HTML of `/identify/photo` now sends `Permissions-Policy: camera=(self), microphone=(), geolocation=()` (`PHOTO_PERMISSIONS` in `src/respond.js`, `camera: true` on `PHOTO_PAGE` in `src/site.js`). The CSP is unchanged (the video plays from a stream object, not a `blob:` URL). The sound page still has no camera (PR #187; `STATE.md`; `src/static.js`).
- **Live loop.** One frame at a time, at most 10 per second (`LIVE_EVERY_MS`), with at least 30 ms of rest. Both models run in the worker so the video is not held up. The name comes from `liveNext` (pure, tested): average of the last 5 frames with a bird; shown once it has led for 3 frames running; may be a family; after 3 frames with no bird the average starts again. A screen wake lock is requested, as Listen mode already does (`STATE.md`; PR #187).
- Accuracy on the 5,889 held-out photos, measured by `training/identify-photo/score-detect.py` and recorded in `docs/identify-photo-model.md` and the new `training/identify-photo/detect-efficientdet-lite{0,1,2}.json` files: automatic crop 83.8% species first / 92.6% top three / 92.6% family, versus 81.3 / 91.3 / 91.0 for the whole middle square and 82.7 / 92.5 / 92.2 for the middle 88%. A bird is found in 90.4%. There were never hand-crop results to compare with (PR #186).

### Design

- New Live UI in `src/identify-photo-page.js` and 11 lines of CSS in `src/style.js`: `.identify-live-offer`, `.identify-live-frame` (black background, video plus an absolutely positioned overlay canvas for the outline), `.identify-live-name` (bold sans, 1.3 rem), `.identify-live-view` (muted “bird in view” line), `.identify-live-zoom` (slider). Hold and Stop sit together; the zoom slider is shown only when `track.getCapabilities().zoom` exists, otherwise a note tells the visitor to take a photo.
- Copy on the page says Live uses more battery than a photo, cannot zoom as far as the phone's camera app, and that no picture leaves the device (`LIVE_NOTE` in `src/identify-photo-page.js`).
- Screen readers: the live name is not a live region; the status line says “Seen: \<name\>.” once when the name changes. A text line says whether a bird is in view, so the mode does not depend on seeing the outline (`STATE.md`; PR #187; issue 181).

### Tooling

- New scripts: `training/identify-photo/strip-detector.py` and `score-detect.py`, plus the three `detect-efficientdet-lite*.json` result files and `test/fixtures/identify-photo/detector-barbet.json`. Training README steps 10–12 document how to fetch Google's file, strip it, and score it (`training/identify-photo/README.md`).
- Tests grew with both PRs. PR #186: `pnpm test` 309 pass, 0 fail, 5 skipped (the skipped ones are sound-page tests that need the sound model). PR #187: 319 pass, 7 skipped, 0 fail; lint, `kv:dry-run` and `check` pass. `test/identify-photo-browser.test.js` now needs `data/models/bird-detector.tflite` as well as the photo model, and is skipped without either, so it is skipped in CI (PR #186, `STATE.md`). `test/identify-layout-browser.test.js` covers automatic cropping, a second bird and the upgrade offer with stand-ins. Live is driven in Chromium and WebKit by replacing `getUserMedia` with a canvas stream of the test photo (PR #187; `STATE.md`).
- Desktop Playwright figures in `STATE.md`: 8.8 frames a second in Chromium, 8.2 in WebKit, on a 500×375 stream (PR #187 body quotes 8.7 and 8.1). These “say nothing about phones”.

## Mistakes, reverts and gotchas newly learnt

No revert appears in the four commits. The new gotchas, each with its cause, are:

1. **LiteRT.js cannot run a stock EfficientDet-Lite file.** Cause: the last op, `TFLite_Detection_PostProcess`, has outputs of no fixed size; the run fails with “Insufficient buffer size”. The fix was to strip that step and do box picking in the page, with a fixture that holds the page's arithmetic to the Python scorer (PR #186; `STATE.md`; `docs/identify-photo-model.md`; `strip-detector.py`).
2. **A tight crop is worse than no detector.** Cause: the recogniser was trained on photos with some surroundings. Score/margin grid in `docs/identify-photo-model.md`: margin 0 is worse than the middle-88% baseline; 35% margin at score 0.3 was chosen as the middle of a flat range.
3. **The next-larger detectors are not worth shipping yet.** Cause: EfficientDet-Lite2 gains only 0.3 points on species first for 2.8 MiB more download and about twice the work (Google's published phone figures cited in the model card: 36 ms vs 69 ms). Lite0 was kept; Lite2 is documented as a drop-in if phone photos show that small birds are missed too often (`docs/identify-photo-model.md`; PR #186).
4. **Deploying the Worker before publishing the detector leaves the new feature broken in a quiet way.** Cause: `models:publish` is still a separate, token-gated step, and `STATE.md` at `main` still says the detector is “Not published yet”. If the Worker is deployed first, the page falls back to manual crop and its offer to download the detector fails (PR #186 “Before deploying”).
5. **Existing visitors must not be forced to download the extra 4.4 MiB.** Cause: they already have the recogniser cached. The page offers the detector; the installed-app photo-model option shows as an update (PR #186; `STATE.md`; `#identify-upgrade` in `src/identify-photo-page.js`).
6. **Held-out iNaturalist photos understate the hard case.** Cause: the test photos are at most 500 pixels on the longer side and mostly already framed on the bird. A distant bird in a 12-megapixel phone photo is where the detector will miss most; it sees the whole photo at 320 pixels (`STATE.md`; `docs/identify-photo-model.md` “What was not measured”; PR #186 “Not verified”).
7. **“Another bird” at score 0.3 is mostly not a second bird.** Cause: on the test photos, 15.2% have two or more boxes at 0.3 and only 5.9% at 0.5, and most of those photos show one bird; fainter boxes are often leaves or stones. The 0.5 cut-off was not checked by eye (PR #186; `docs/identify-photo-model.md`).
8. **Live browser tests do not meet the issue's own “Done when” for tests.** Cause: issue 181 asks that “Browser tests drive it with a recorded video fed in as the camera.” PR #187 feeds a still test photo, shifted a few pixels each frame, because “the repository has no such video” (`STATE.md`; PR #187 “Not done”).
9. **Hold can disagree with the live name.** Cause: Hold re-runs the ordinary photo path on the frame, so its first answer can differ from the smoothed live name (`STATE.md`).
10. **No real phone has been measured for auto-crop or Live.** Cause: the work was merged from desktop Playwright and the held-out photo set. Unchecked, as listed in `STATE.md` and PR #187: frame rate, battery and heat, whether iOS Safari and Chrome on Android offer `zoom`, the camera in the installed app on iOS, what iOS does to the stream when the app is backgrounded, the 60-second idle limit in the field, and Live with no signal. This is why issue 181 stayed open.

## Process changes

- **How agents work.** The gotchas already in baseline `STATE.md` were not edited in this range (the `STATE.md` patch only adds the issue 180 and 181 sections and tightens the identify-by-photo bullets). Rules that still stand: only [@ftruter](https://github.com/ftruter) may approve or merge; agents must not merge; prefer a lean, short-lived session; do not hand work to a long-lived cloud agent unless the owner explicitly asks; one PR per family and do not stack once the owner squash-merges; confirm `mergeable: true` and `mergeable_state: clean` before asking for a merge (`STATE.md` at `main`, “Gotchas” and the project rules at the top).
- **Testing.** The four pre-PR checks are unchanged: `pnpm test`, `pnpm run lint`, `pnpm run kv:dry-run`, `pnpm run check` (`STATE.md` “Checks”). What changed is the identify-photo suite: layout tests use stand-ins so CI can run them without model files; real-model browser tests now need both the recogniser and the detector and will be skipped in CI (PR #186). Live tests mock `getUserMedia` rather than using a recorded video (PR #187). “Not measured” lists are written into `STATE.md` instead of implied.
- **PR rules.** A new, practised rule from PR #187: **do not close an issue from the implementing PR when the issue's “Done when” still needs real-device checks.** The PR body says so in the first paragraph: “For #181. It does not close the issue by itself: the phone checks in ‘Done when’ are still to do.” Issue 181's “Done when” requires Live to name a bird on a current iPhone and a current Android phone, in Safari or Chrome and in the installed app, with no signal once the models are downloaded, and with no frame leaving the device.
- **Tester feedback the owner is now waiting on.** The project has paused on that open issue. PR #187 and `STATE.md` (“Not measured or checked: any real phone”) are the in-repo record of what testers need to try: Live (and auto-crop) on a current iPhone and a current Android phone, in the browser and the installed app, including zoom, backgrounding, battery and heat, offline use once the models are downloaded, and whether the 60-second idle limit suits the field. Earlier unmeasured phone work from before this range (Listen mode, the installed app itself, recognition-time rows for an iOS 26 compatibility-build iPhone, an iPad and an Android phone in the issue 178 table) is still listed as unmeasured in `STATE.md` at `main`, but it was already in the baseline lessons and was not newly opened here.
